# ADR 0006: `dist/libro.cyr` as committed-artifact distribution contract

**Date:** 2026-04-19
**Status:** Accepted

## Context

libro is a Cyrius library consumed by multiple downstream projects
(daimon, aegis, stiva, sigil, ark). Cyrius has no package manager
in the crates.io sense; downstream consumers express dependencies
via `[deps.libro]` in their own `cyrius.cyml` and `cyrius deps`
resolves them by pulling a specific git tag and expecting a
canonical bundle file at a known path.

Patra (libro's peer first-party project) established the convention:
a single bundled source file at `dist/<name>.cyr`, committed to the
repo, produced by `cyrius distlib`, consumed by downstream via
`cyrius deps`. The bundle inlines every `[lib] modules` entry in
the manifest's declared order so a consumer can `include
"lib/libro.cyr"` (after stdlib + sigil + patra) and get the full
library in one compilation unit.

Every pre-2.0 libro tag **did not ship this file**. A downstream
pulling any 1.x tag got a 404 on `cyrius deps`. This had not been
noticed because the consumers (above) were either still on local
source paths or hadn't upgraded past the Rust era. The 2.0 sprint
formalized the contract per `DEPS-PATTERN.md`.

## Decision

1. **`dist/libro.cyr` is committed to the repo** and is the sole
   distribution contract for downstream consumers. `cyrius deps`
   resolves `[deps.libro]` by fetching this file at a tag.
2. **It is generated by `cyrius distlib`** from the `[lib] modules`
   list in `cyrius.cyml`. That list mirrors the `include "src/*.cyr"`
   lines in `src/main.cyr` (and CI enforces this — see below).
3. **CI gates on freshness**: any PR that edits `src/*` without
   running `cyrius distlib` and committing the regenerated file
   fails the "dist/libro.cyr is up-to-date" step.
4. **CI gates on manifest completeness** (added 2.0.1 after this
   class of drift was observed): every `include "src/<file>.cyr"`
   in `src/main.cyr` must appear in `[lib] modules`, and vice
   versa. This closes a previously-silent gap where the
   manifest could be stale while the dist artifact remained
   "consistent" with itself.
5. **The dist bundle is not self-contained.** `cyrius distlib`
   reports `warn: dist bundle has compile errors — likely missing
   symbol from a stripped include` and identifies `SIG_ALG_ED25519`
   as the symbol. This is expected: sigil / patra / stdlib are
   upstream deps consumers include separately. The bundle compiles
   cleanly when preceded by the standard consumer include order:
   `stdlib → sigil → patra → libro`.
6. **Release gate asserts `VERSION == cyrius.cyml version == dist
   header version == git tag`** before any release artifact is
   built.

## Consequences

- **Consumer integration stabilizes.** Downstream can pin a libro
  version via `[deps.libro] tag = "2.0.3"` and `cyrius deps`
  retrieves the committed dist deterministically.
- **The manifest's `[lib] modules` list is load-bearing.** It is
  the source of truth for what `cyrius distlib` bundles. If a
  module is added to `src/main.cyr` but not the manifest, the
  dist silently ships without it. 2.0.0 hit exactly this
  (`chain_io.cyr` went into `main.cyr` but not `[lib] modules`),
  so advertised APIs `chain_export` / `chain_import` were missing
  from `dist/libro.cyr` until the 2.0.0 hardening pass. The CI
  manifest-completeness gate now prevents recurrence.
- **Version parity is release-blocking.** Four places must agree
  (`VERSION`, `cyrius.cyml` `version = "…"`, dist header
  `# Version: …`, git tag). `scripts/version-bump.sh` edits the
  first two; `cyrius distlib` regenerates the third; the user
  creates the fourth. If any drift, the release workflow fails
  on the version-parity step.
- **Dist size is a release metric.** `wc -l dist/libro.cyr`
  at tag time is recorded in the CHANGELOG validation block. 2.0.3
  is 4489 lines.
