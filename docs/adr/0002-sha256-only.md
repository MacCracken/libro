# ADR 0002: SHA-256 Only (No BLAKE3)

**Date:** 2026-04-09
**Status:** Accepted (implementation moved to sigil in 1.0.2)

## Context

The Rust version defaulted to BLAKE3 (4-10x faster than SHA-256) with SHA-256 available via the `sha256` feature flag. BLAKE3 is not available in the Cyrius stdlib and would require porting ~2,000 lines of SIMD-optimized code.

## Decision

Use SHA-256 (FIPS 180-4) exclusively. Implement from scratch in Cyrius (~250 lines).

## Consequences

- SHA-256 is universally recognized and FIPS compliant
- No SIMD optimization — pure scalar 32-bit masked arithmetic on i64 values
- Performance is adequate: 9us per 64-byte hash, 1.4ms to verify 100-entry chain
- BLAKE3 can be added later if Cyrius stdlib gains crypto modules
- Existing Rust chains using BLAKE3 are not cross-verifiable with Cyrius chains (expected — the `hash_algorithm` field documents which algorithm was used)
- **Superseded by:** sigil will become the single crypto primitive source for the AGNOS ecosystem. When sigil converts to Cyrius, libro's `src/sha256.cyr` will be replaced with sigil's verified SHA-256. See roadmap for timeline.

## Status note (2.11.2)

The decision stands: SHA-256 is libro's only entry hash (`HASH_ALGORITHM` in
`src/hasher.cyr`), and it is part of the entry preimage since 2.8.11. The
"Superseded by" bullet above was about the implementation, not the decision,
and it happened: libro 1.0.2 deleted `src/sha256.cyr` and hashes with sigil's
SHA-256, which also dispatches to the SHA-NI instructions where the CPU has them
(`sigil_sha_ni`). So the "no SIMD optimization" and the 9 µs / 1.4 ms figures are
1.0.0's.
