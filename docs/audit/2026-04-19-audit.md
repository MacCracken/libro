# Libro P(-1) Security Audit — 2026-04-19

**Scope:** Pre-sprint-1.1.0 hardening pass on libro v1.0.4 (Cyrius 5.4.2).
**Focus:** Cumulative-state crash in `test_patrastore_append_load` (tracked
in `issue-to-fix.md`), and adjacent input-handling review.

## Finding 1 — Use-after-free on patra result-set pointers (HIGH)

**Location:** `src/patra_store.cyr:_patrastore_row_to_entry` (v1.0.4 and
earlier, including the cc3-era v1.0.3 bundle).

**Description:** `_patrastore_row_to_entry` built `AuditEntry` fields by
calling `str_from(patra_result_get_str(rs, row, col))`. `patra_result_get_str`
returns a raw pointer into the result-set's internal data buffer, and
`str_from` does **not** copy — it wraps the pointer. The calling site
`patrastore_load_all` then invokes `patra_result_free(rs)` **before
returning** the vector of entries. All ten `Str` data pointers on every
returned entry pointed into freed memory.

**Exploit path:** Any subsequent field access (e.g. `entry_hash`,
`entry_source`, `str_eq` on a loaded entry) dereferenced freed memory.
In the gated test suite this surfaced as a SIGSEGV inside `memeq`
(called transitively via `str_eq`) during the hash-preservation assert
in `test_patrastore_append_load`. The crash was "layout-dependent" —
adding `println` statements shifted heap layout and could mask the
fault — which matches a classic use-after-free signature.

**Crash localization (pre-fix, cc5 5.4.2):**
```
Stack trace of thread 1062248:
#0  memeq + 0x71              (0x400219)
#1  test_patrastore_append_load + 0x4b2 (0x454c84)
#2  main + 0x376              (0x4559d5)
#3  main + 0x30a9             (0x458708)
```

**Root cause:** `str_from(cstr)` is a pointer-wrapper, not a copy. Callers
that receive a cstr pointing into ephemeral storage (a result buffer, a
file read buffer, etc.) must copy before wrapping. There was no in-tree
helper for "copy cstr into heap then wrap" — every caller had to know
the lifetime contract implicitly.

**Severity:** HIGH. Exploitable whenever a caller invokes PatraStore's
load/query path and subsequently inspects the returned entries. Not
remotely triggerable without also compromising the audit database, but
reliable denial-of-service inside any consumer (daimon, aegis, sigil,
stiva, ark) that reads back from PatraStore.

**Fix (v1.1.0):** Added `_ps_copy_cstr(cstr)` helper in
`src/patra_store.cyr` that allocates a fresh null-terminated buffer,
`memcpy`s the cstr into it, and wraps *that* buffer as a `Str`. Every
`patra_result_get_str` in `_patrastore_row_to_entry` now routes through
this helper. Entries returned by `patrastore_load_all` now own their
string memory outright, independent of the result-set lifetime.

**Validation:** All 7 PatraStore tests + 12 Gap coverage tests relanded.
Suite grew 204 → 251 tests, 0 failures.

## Finding 2 — Patra bundle staleness (MEDIUM)

**Location:** `lib/patra.cyr` (was v0.14.0 bundle, 3013 lines).

**Description:** libro shipped a v0.14.0 patra bundle; upstream is at
v1.1.1 with substantial storage, WAL-overflow, and query-planner fixes
across v0.15–1.1.1. No API drift — drop-in replacement.

**Fix (v1.1.0):** Copied `dist/patra.cyr` from
`~/Repos/patra/dist/patra.cyr` (v1.1.1) over `lib/patra.cyr`. All
consumers' API calls unchanged.

**Severity:** MEDIUM. Upstream has closed several storage bugs and
hardened the SQL parser since v0.14.0. Staying on v0.14.0 meant libro
inherited every closed defect.

## Finding 3 — Shared-buffer Str wrapping in FileStore (MEDIUM — fixed in 1.1.1)

**Location:** `src/file_store.cyr:filestore_load_all` (line 108 pre-fix).

**Description:** `str_new(_fs_buf + pos, line_len)` wrapped a pointer
into the globally-allocated `_fs_buf` read buffer, then handed that
`Str` to `_filestore_parse_entry` → `json_parse`. `json_parse` in
`lib/json.cyr` also wraps (`str_new(data + qs, …)`) — so every `Str`
field stored on a loaded entry ultimately pointed into `_fs_buf`.

`_fs_buf` is a *global* read buffer, reused across calls. A second
`filestore_load_all` — for the same or a different store — overwrites
the buffer contents in place, aliasing the first call's entries onto
the second call's bytes.

**Severity upgrade rationale:** LOW (defense-in-depth) in v1.1.0;
reclassified MEDIUM during the v1.1.1 CI/refactor pass once a
regression test was written:
`test_filestore_load_survives_second_load` deterministically reads
`"beta_src"` out of an entry that should have held `"alpha_src"` on
the pre-fix binary (`2 failed` on the targeted asserts). That makes
this a reliable silent-corruption bug in any consumer that keeps a
`filestore_load_all` result around across another load.

**Fix (v1.1.1):** `src/file_store.cyr:filestore_load_all` now clones
each line with `str_clone(str_new(_fs_buf + pos, line_len))` before
passing it into `_filestore_parse_entry`. Clone buffers live in the
bump allocator and are not reused, so every Str derived from the
parse references stable memory. Regression test
`test_filestore_load_survives_second_load` added under the FileStore
test group — flips from PASS → FAIL the moment the clone is removed.

**Validation:** 251 → 255 tests (+4 asserts in the regression test),
0 failures. Pre-fix binary fails exactly those 4 asserts, proving the
test is load-bearing.

## Deferred / not-this-pass

- **Cyrius stdlib `_sb_grow` bounds.** Investigated as a suspect for
  Finding 1; ruled out — the grow path correctly bumps cap via `alloc`
  before `memcpy`. Not a bug.
- **Heap reset shim (`alloc_reset()`).** The v1.0.3 shim that reset the
  bump allocator before the PatraStore block was a band-aid — it
  reduced aliasing pressure but did not fix the underlying
  use-after-free. Dropped in v1.1.0; Finding 1 is the proper fix.
