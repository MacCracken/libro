# Security audit — 2026-08-22, round 2 (libro 2.8.11 → 2.8.12)

**Scope:** the code release 2.8.11 introduced, the modules round 1's own
completeness critic named as unexamined, and incomplete migrations — plus
`src/tpm_anchor.cyr`, which no audit had ever reached because it sits behind
`-D LIBRO_TPM` and had never been in a compilation unit under review.
**Method:** seven lenses, each finding adversarially verified by a separate
reviewer instructed to refute it and permitted to build probe binaries.
**Outcome:** 33 filed, **28 confirmed**, 5 refuted. Five further defects were
found by hand before the sweep reported. All 33 are fixed in 2.8.12.

⭐ **The headline is not any single defect. It is that most of what round 2
found was introduced by round 1's fixes.** 2.8.11 repaired 26 defects in one
release; that release was itself a large, unreviewed change, and reviewing it
turned up a comparable number again. The five findings the sweep *refuted* are
the same story from the other side: they described defects that were fixed
while it ran, and the verifiers checked the live tree and correctly rejected
them.

---

## Defects introduced by 2.8.11

Listed first because they are the most transferable result.

| Defect | How it got there |
|---|---|
| `libro_is_error` dereferenced its argument, crashing on the documented usage | Introduced to make a dangerous API safe; the predicate was itself unsafe on the count-returning APIs it was documented for |
| `_merkle_tag` staged a byte in a process-global buffer | The *same* pattern the same release removed from `hash_field`, reintroduced in the fix for it |
| `_fsj_pos` returned a value through a process-global | New parser, old mistake — the `_fsp_pairs` global two functions below had just been removed for this |
| `_fsj_read_scalar` returned a view where its sibling returned a copy | Two lifetimes from one call site |
| `_pfj_parse_string` could not decode `\u00XX` | The escaper started emitting it; the third decoder was not updated |
| proof JSON never emitted `hash_algorithm` | Harmless until the same release put the field in the preimage |
| The canonical hasher allocated 110× its input | A fixed 1,032-byte buffer per number in the new normalizer |
| The escaping migration stopped four fields short | `source`/`action`/`details`/`agent_id` fixed; `timestamp`/`prev_hash`/`hash`/`hash_algorithm` left raw |
| The signature-length guard skipped the HYBRID arm | Written as `if (alg != SIG_ALG_HYBRID)` |
| The length guard checked length but not hex validity | `hex_decode` returns 0 for non-hex, which then reached sigil as a null pointer |

The pattern is consistent: **a fix applied to *most* instances of a class, and
a new mechanism carrying the old mechanism's flaw.** Neither is caught by a
green suite, because both produce code that works for everything the suite
exercises.

## Finding 1 — canonical JSON did not canonicalize (High)

ADR 0007 has claimed since 2.0 that canonical means "the same logical value
produces the same hash regardless of incidental formatting", citing RFC 8785.
Measured on 2.8.11:

```
{"a":"A"} vs {"a":"A"}   -> different digests
{"a":1}   vs {"a":1.0}        -> different digests
{"a":1}   vs {"a":1e0}        -> different digests
```

Strings were hashed with escapes intact, numbers with their source spelling.
Safe in direction (non-normalization, not collision) but a much weaker
equivalence than the documentation asserted, and a real problem for any
consumer whose `details` passes through a second JSON library.

Fixed by decoding and minimally re-escaping strings (values *and* keys, with
keys sorted by decoded form), and emitting numbers in an exact plain decimal
computed with digit-string arithmetic. Surrogate pairs decode to real UTF-8
rather than CESU-8; lone surrogates are rejected.

⚠ **A validator/decoder disagreement was caught during this work and is worth
recording.** The first surrogate implementation had `json_str_decode` rejecting
a lone surrogate while `_cjv_string` still accepted it — so a document would
pass validation and then take the emitter's verbatim fallback. That is exactly
the failure the validate-then-emit design exists to prevent, and it was found
by a probe rather than by the suite.

## Finding 2 — empty `details` collided with the literal `null` (Medium)

`canonical_json_hash_str` short-circuited an empty document to the four bytes
`null` — which is also the canonical emission of the valid document `null`. Two
distinct stored records, one preimage, in the single branch that skipped the
canonicaliser 2.8.11 had just hardened.

## Finding 3 — the tree-head signature covered only the root (Medium)

`timestamp` was unauthenticated and read by no verifier, so a holder of a valid
proof could restate when the log was attested. Now signed as part of
`tree_head_digest(root, tree_size, timestamp, algorithm)`.

## Finding 4 — three more self-referential proofs (Medium/High)

2.8.11 fixed inclusion proofs verifying against their own embedded root. The
same shape remained in **consistency proofs**, in **anchors** (only the
anchor's self-hash was checked, so an anchor for a different tree reported
`ANCHOR_VALID`), and in the leaf half of inclusion — `merkle_verify_proof_against`
answers "does some leaf reach this root", never "is *my entry* in this tree".

Finding one instance of a class and fixing only that instance is the recurring
theme of this report.

## Finding 5 — front-truncation verified clean (Medium)

`verify_chain` validated linkage only for `i > 0`, so `entries[0].prev_hash` was
never examined. Deleting entries from the *front* of a stored log produced a vec
that verified completely. `chain_verify` had guarded this since 2.0; the four
store paths call `verify_chain` directly and inherited the hole.

## Finding 6 — sibling-key injection through four unescaped fields (High)

Reproduced end to end by the verifier: a crafted `timestamp` survives a load,
and after an archive/rotate cycle the stored record reads back with
attacker-chosen `source` and `action`. A raw newline in the same field splits
the record and it is dropped with no error. `_fsj_lookup`'s first-match rule
amplified it, so duplicate keys are now rejected outright.

## Finding 7 — the verifier crashed on a malformed signature (High)

Confirmed directly: a null signature pointer into `ed25519_verify` exits 139.
A correct-length non-hex signature decoded to exactly that. The HYBRID arm
skipped the guard entirely.

## Finding 8 — heap overflow in the RFC 3161 request builder (High)

`ts_request_to_der` wrote a caller-sized message imprint into a fixed
`alloc(48)`; a SHA-512 digest overflows it by 18 bytes.

## Finding 9 — `src/tpm_anchor.cyr`, never audited (Medium)

Behind `-D LIBRO_TPM`, so no previous lens had it in the compilation unit. It
forwarded caller-supplied `pcr_indices` into sigil's `tpm_pcr_selection`, which
sizes its buffer at three bytes per index — a large index overflows it. Plus a
`Str` passed where a NUL-terminated cstr was expected, and a missing null check.

## Method notes

**Four mutations survived and the tests were wrong, not the fixes.** Recorded
because a surviving mutation is the only signal that a test proves less than it
appears to:

- The leaf-domain test compared `merkle_leaf_hash` against itself, so removing
  the tag moved both sides.
- The sort test proved order-*independence*, which a reversed comparator also
  satisfies; pinning the canonical bytes was required.
- The control-byte test used only bytes with shorthand escapes, leaving the
  `\u00XX` branch unexercised.
- The junk-DER test was rejected on length before tags were consulted.

Two further mutations were **ineffective rather than survived** — one mutated a
buffer-size initializer that the next line overwrote, another removed an inner
null check while an outer one still caught it. Both looked like passing
mutations and were neither.

**Two invalid measurements were caught and discarded**, which is the other half
of the method:

- A 6.5.34-vs-6.5.35 codegen differential reported "byte-identical" twice. Both
  harnesses were insensitive: `PATH` selection changes what `cyrius --version`
  reports but not which `cycc` runs, proven by compiling cyrius's own changed
  corpus files and getting identical output; `cyriusly use` only rewrites the
  manifest pin. No differential was possible with the available tooling and
  none is claimed.
- A benchmark run taken while seven audit agents saturated the machine showed a
  5× swing on one bench. Discarded rather than recorded.

## Not fixed in 2.8.12

- **RFC 3161 token verification.** Unchanged from 2.8.11: DER tags are checked
  and a granted response must carry a token, but the TSA's CMS signature is not
  verified, TSTInfo is not parsed, and the nonce is not checked. Needs
  CMS/PKCS#7 against a certificate chain, which belongs in sigil.
- **Full RFC 8785 number formatting.** libro's decimal form is exact; JCS's is
  shortest-round-trip. They agree on every short expansion. Closing the gap
  needs a correct shortest-round-trip float formatter, which is a poor thing to
  write under time pressure into a hash preimage.
- **`_cjh_emit_object`'s remaining 16× allocation amplification.** Down from
  110×. The rest is vec growth and a decoded `Str` per key; removing it needs a
  reusable scratch arena. Bounded by a test so it cannot regress further.
- **Thinning `[deps.bayan]`.** Carried from 2.8.11; still a dep-graph change.
