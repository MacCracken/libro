# Security audit — 2026-08-22 (libro 2.8.10 → 2.8.11)

**Scope:** all 22 modules in `src/`, plus the CI gates, at the 2.8.10 tree
(toolchain pin 6.5.31) and re-checked at 6.5.34.
**Method:** a P(-1) sweep of seven independent lenses over the source, each
finding adversarially verified by a separate reviewer instructed to refute it,
followed by a completeness pass asking what the sweep had missed. 40 findings
filed, 35 survived verification, 5 refuted. The completeness pass then found
six more that no lens had been pointed at — including one of the two most
serious defects in the report.
**Outcome:** 26 distinct defects, all fixed in 2.8.11. Every one was reproduced
with a probe binary built against the real tree before it was fixed, and every
fix is mutation-verified.

## Finding 1 — the canonical-JSON hasher accepted junk (Critical)

`src/entry.cyr`, `_cjh_emit_object`.

The emitter's `else { pos += 1; }` fallthrough silently discarded any byte it
did not recognise, the `:` between key and value was optional, and bytes after
the top-level value were ignored. Measured on the 2.8.10 tree — all five inputs
produced digest `015abd7f5cc57a2dd94b7590f04ad8084273905ee33ec5cebeae62276a97f862`:

```
{"a":1}
{ZZZZ"a":1}
{"a":1 JUNK}
{"a" 1}
{"a":1}XXXXXXX
```

**Impact.** This is a forgery primitive against the product's core claim. The
injected bytes sit inside a stored `details`, so `{"a":1}` could be rewritten to
`{approved_by_legal"a":1}` with the entry hash, the chain linkage, the Merkle
root and any tree-head signature all unchanged, and `verify_chain` returning
clean. Any injected text free of `"`, `,` and `}` works. `details` is untrusted
on every ingress path — proof import, JSONL reload, PatraStore row — and is the
field consumers routinely fill from their own callers' data.

**Why 661 tests missed it.** Every in-tree `details` is `{}` or a small
well-formed object produced by libro itself. The hasher was never fed anything
it had not written.

**Fix.** Strict validation (`canonical_json_is_valid`) before any emission.
Well-formed input takes the unchanged canonical path and produces an identical
digest. Malformed input falls back to a `0x00`-tagged, length-prefixed hash of
the raw bytes — distinct from every canonical emission, and injective among
malformed inputs.

## Finding 2 — `hash_algorithm` was outside the entry preimage (High)

`src/entry.cyr:entry_compute_hash` fed fields 1–8 and never field 11. Measured:

```
entry_verify before        = 1
entry_set_hash_algorithm(e, "md5-lol")
entry_verify after tamper  = 1
```

Every serializer round-trips the field and `_filestore_parse_entry` reads it
straight off disk, so it was an attacker-writable field on a tamper-evident
record. The sibling struct already length-prefixes its `hash_alg`
(`anchor_compute_hash` step 5) — the inconsistency was the tell.

**Second-order finding.** Adding it to the preimage immediately turned the
PatraStore suite red, exposing Finding 8: `patrastore_append` had been binding
the column with `strlen()` on a `Str` fat pointer, so column 9 held the struct's
raw bytes on every INSERT since the column existed. Latent only because nothing
hashed the field.

## Findings 3 and 4 — Merkle construction (High)

`_merkle_hash_pair` was `HASH(left || right)` with no domain tag, and a leaf was
the bare entry hash. Both are 64-char hex, so a leaf and an internal node are
indistinguishable and an internal node can be presented as a leaf — the textbook
second-preimage shape. Now RFC 9162 §2.1.1 tagging.

Separately, `merkle_build` duplicated an odd trailing node (`right = left`)
while `merkle_canonical_root` — already present in the same file — promoted it
per RFC 9162 §2.1.2. So `{d}` and `{d, d}` shared a root, and the tree's two
root definitions disagreed at every non-power-of-2 size, which means a proof
bundle's inclusion root and its consistency root could never have been bound to
one another. `merkle_build` now promotes; equality with `merkle_canonical_root`
is asserted at sizes 1 through 9.

## Finding 5 — an inclusion proof verified itself (High)

`_proof_verify_common` called `merkle_verify_proof(mp)`, which recomputes the
root from the path and compares it to the root **carried inside the same
proof**. Nothing bound that to `sth_root`, so a bundle could carry inclusion
proofs for a completely different tree and report `inclusions_valid = 1`.
`merkle_verify_proof_against(mp, expected_root)` now takes the trusted root.

## Finding 6 — a deleted audit log verified clean (High)

`filestore_load_all` returned `vec_new()` when the open failed — byte-identical
to a healthy empty log. `filestore_load_and_verify` verified that empty vec,
found nothing wrong, and reported success. A deleted, renamed or
permission-stripped audit log therefore "verified clean". `patrastore_load_all`
had the same shape on query failure.

This is one instance of a class the sweep found four times: libro returns either
a value or an error struct, both non-zero pointers, so `if (r != 0)` reads a
failure as a success. Rather than patch each site, 2.8.11 adds a discriminator —
every error constructor stamps a magic at offset 0 and `libro_is_error(p)` /
`libro_is_ok(p)` answer the question. The `error` struct grew a `magic` field at
+0 (7 fields, 56 bytes) and the CI raw-offset bound moved 6 → 7.

## Finding 7 — SQL string interpolation on the read path (High)

`patrastore_by_source` built `WHERE src = '<source>'` by concatenation. The
write path was migrated to bound parameters in 2.8.1 after exactly this bug
corrupted argonaut's log; the read path was not. A `source` containing a single
quote produced malformed SQL and returned zero rows — an audit-log query
silently answering "no such events" — and a crafted value could widen the
predicate to the whole table. Now bound.

## Findings 9–14 — crash and corruption on untrusted input

Each was reproduced with a probe binary.

- **`proof_from_json`** stored an integer in `sth.algorithm`, a `Str` slot whose
  only consumer calls `str_len()` on it. Re-serializing a parsed proof
  evaluated `str_len(1)` and segfaulted (measured exit 139) for any JSON whose
  tree head says `"algorithm": "ML-DSA-65"`. On the other algorithms there was
  no crash but the algorithm identity was dropped on every round trip.
- **Signature verification** decoded hex before checking length: a 2-character
  signature became a 1-byte buffer that `ed25519_verify` read 64 bytes from
  (ML-DSA, 3309), and an absent signature reached `str_data(0)`. Reachable from
  `proof_verify_signed` with an attacker-supplied proof.
  `verifying_key_from_bytes_alg(bytes, SIG_ALG_HYBRID)` built a key over a
  zero-byte allocation because `_sig_pk_bytes` has no HYBRID arm — and the
  file's own doc comment recommended that constructor for hybrid, so a
  correctly-signed hybrid entry could never verify.
- **`source` / `action` written unescaped** made a quote produce an unparseable
  line, so the entry was silently dropped on reload.
- **Missing `timestamp` or `prev_hash`** stored a NULL `Str` that every later
  `str_len()` dereferenced.
- **No recursion bound** in the mutually-recursive canonical-JSON emitters: about
  130 KB of nested array opens exhausted the stack, on append and on every
  subsequent verify.
- **`hash_field` staged its length prefix in a process-global buffer**, so two
  threads hashing concurrently produce wrong digests — silently, as false
  integrity violations. Threaded reads became a supported shape in 2.8.9, and
  libro is consumed by servers.

## Finding 18 — `_query_parse_ts` decided what gets deleted (Medium)

It read 20 bytes from a `Str` of any length and validated nothing:

```
""                     -> -1554199139047   (read past a zero-length Str)
"2026"                 ->  1358407617
"not-a-timestamp!!!!!" ->  2114694242535
"2026-08-22T10:00:00Z" ->  1787392800      (correct)
```

Timestamps arrive from disk and from proof bundles verbatim, so one garbage
value made `query_after` / `query_before` silently include or exclude a record.
The same function drives retention, so it also selected entries for deletion:
with a truncated timestamp, `retention_sox()` (keep 7 years) returned
`split_index = 0`. Both callers now fail closed.

## What the sweep itself missed

Recorded because it is the more useful half of the method. Nine of 22 modules
produced no surviving finding from any lens. The completeness pass examined them
directly and found four real defects there — `_query_parse_ts` (18), the HYBRID
key constructor (10), `chain_import`'s header handling (19), and `export.cyr`'s
weaker serializer (25) — plus the observation that no lens had asked *which
fields are inside the preimage* as opposed to *how the hash is computed*, which
is what surfaced Findings 1 and 2.

The lesson generalises: seven lenses aimed at computation all missed the two
defects in what was being fed to it.

## Note on the 21 build warnings

The 2.8.10 build emitted 21 `assigning non-pointer to typed pointer` warnings.
All 21 were verified benign — `#derive(accessors)` emits getters with no
declared return type, so a `Str`-typed local reassigned from one warns about a
value that is a `Str` at runtime.

The one real instance of that exact class — Finding 9, an integer written into a
`Str` slot — **did not warn**, because the diagnostic fires on assignment into a
typed local, not on argument passing into an untyped parameter. A clean build
carrying 21 ignorable warnings is how it survived. All five build targets are
warning-free as of 2.8.11.

## Not fixed in 2.8.11

- **RFC 3161 token verification.** DER tags are now checked and a granted
  response must carry a token, but libro still does not verify the TSA's CMS
  signature, does not parse TSTInfo to confirm the token's `messageImprint`
  matches the hash, and does not check the nonce. A genuine response for one
  hash can still be presented alongside another. This needs CMS/PKCS#7
  verification against a certificate chain, which belongs in sigil. Tracked on
  the roadmap; `ts_attestation_new`'s doc comment states the limit.
- **Thinning `[deps.bayan]` to the json sub-bundle.** libro uses two bayan
  functions and pulls the 641 KB monolith. Worth ~200 KB of binary, but it
  changes the dep graph, and `cyrius.cyml` documents at length why that is not a
  patch-release move. Roadmap.
- **A hash-version discriminator.** 2.8.11 changes the preimage with no
  migration path. A versioned algorithm field would let a future change verify
  old and new entries side by side. Roadmap.
